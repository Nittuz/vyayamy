# Batch 4: Accessibility & Inputs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Impeccable Batch 4 — the accessibility-size hierarchy inversion, unlabeled inputs, the sub-44pt accessory key, keyboard avoidance gaps, and machine-enforcement so the (excellent) manual a11y practice stops regressing.

## Global Constraints

- Design source: 2026-08-22 critique P1 "Accessibility text sizes invert the hierarchy" + audit P2s (36pt accessory key; unlabeled TextInputs) + P3s (KeyboardAvoidingView ×2; a11y lint).
- Caps philosophy (from the type system's own precedent — display variants already cap at 1.2× with documented rationale): metadata must never outgrow the content it labels. `strip` and `label` variants cap at 1.5×. Body/meta text stays uncapped (content scales freely).
- Icon-beside-text: icons that sit inline with scalable text must scale with the font scale, clamped to the same 1.5×. Introduce ONE small helper (e.g. `useFontScale(max?)` reading RN `PixelRatio.getFontScale()`/`useWindowDimensions().fontScale`) in src/ui and apply it at the known offenders: Today's History-link arrow (size 14) and RepeatCard/PlanCard strip-adjacent icons if any. Do not sweep every icon in the app — inline-with-text icons only.
- Unlabeled `TextInput`s get `accessibilityLabel` matching their visible label text: Login (email, password), Profile (display name), ExercisePicker (search), PlanSetup (plan name).
- `NumericStepperView` accessory key `minHeight: 36` → `theme.touch.min` (44).
- `KeyboardAvoidingView` on PlanSetup + Profile, mirroring Login.tsx's exact configuration (behavior/keyboardVerticalOffset).
- ESLint: add `eslint-plugin-react-native-a11y` (devDependency), extend its recommended config in .eslintrc.js. Rule severity policy: rules that pass repo-wide after this batch's fixes → error; rules with pre-existing violations → warn with a one-line note in the eslint config listing why (keeps the 0-errors gate honest without a mass refactor). CI already runs lint — no workflow change needed.
- Tests: extend src/ui/**tests**/textVariants.test.ts to pin the 1.5× caps on strip/label (and that body/meta remain uncapped, display stays 1.2×).
- Gates before each commit; push at batch end + CI watch.
